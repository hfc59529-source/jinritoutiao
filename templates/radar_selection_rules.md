# 爆点文案筛选层规则 V2

## 位置

```text
老师网站爆点文案池
        ↓
爆点文案筛选卡 radar_selection
        ↓
今日入选文案
        ↓
Shared 参数
        ↓
Transform
        ↓
Article Master
```

## 筛选对象

筛选对象不是原始热点，而是老师网站已经生成完成的爆点文案。

默认老师网站产出的文案已经合格，所以这里不判断"文案写得好不好"。

Selection 不负责再次判断"这是不是热点"，只回答：**在今天已经采到的候选爆点中，哪一条最值得占用今天的生产和发布资源？** 这是一个 Ranking（排序）问题，不是 Absolute Scoring（绝对评分）问题。

## ① Hard Gate（硬性门槛，任一 FAIL 直接不发）

Gate 判断"我们有没有足够事实安全地写"，不是判断"这个话题是否敏感/有争议"。争议本身不是拒绝理由，事实不足或风险不可控才是。

| Gate | 判断问题 |
| --- | --- |
| G1｜Source Completeness | 完整雷达详情是否存在？只有列表卡片、没有详情页内容视为不完整。 |
| G2｜Fact Boundary | 核心事实是否足够明确，能否在不自行补事实的情况下成文？ |
| G3｜Risk Boundary | 是否存在当前无法处理的明显事实/法律/安全风险？ |
| G4｜Freshness | 是否仍处于有效发布窗口？（时效在这里作为门槛判断，不作为后续加分项） |

任一 Gate 为 FAIL：**不发**，后续排序不再生效。

## ② Internal Ranking（通过 Gate 后，用于当日候选之间排序）

| 变量 | 判断问题 |
| --- | --- |
| R1｜Public Relevance（大众相关度） | 有多少普通头条用户会觉得"这和我有关"？ |
| R2｜Stakes（利益/风险） | 用户不关注这件事，会损失/错过什么？是否具体（如"570元→5060元"这种明确数字），还是抽象笼统？ |
| R3｜Conflict Clarity（冲突清晰度） | 能否用一句话说清楚矛盾双方和反差？需要解释多段背景才能说清楚，视为低。 |
| R4｜Discussion Tension（讨论张力） | 是否存在普通人能理解的判断分歧（例如"该不该加价"），而不是单纯情绪站队。 |

四项均为高/中/低，**不相加、不折算成分数**，只作为当日候选之间比较优先级的依据。

## ③ External Signal（外部信号，与②并列参考，不相加）

- 老师网站/平台给出的今日爆款评分（0-100）、S/S+标签、热榜位置等，属于来源系统已经计算过的信号。
- **禁止把外部信号和内部排序变量相加**（例如"评分89 + 冲突高(+3) + 利益高(+3)"）：外部评分很可能已经包含了冲突、热度、传播性等因素，再加一次是 Double Counting（重复计权）。
- 外部信号只用于同等条件下的辅助参考，不单独决定优先级。

## ④ 相对排序：P1 / P2 / P3 / 不发

Gate 全部 PASS 后，结合 Internal Ranking 和 External Signal，在**当天候选之间**给出相对顺序：

- **P1**：当天最值得优先占用发布位。
- **P2**：次优先。
- **P3**：有空位再生产。
- **不发**：Gate 未通过，或综合判断不值得占用当天发布位。

P1/P2/P3 不代表达到某个绝对分数线——如果当天候选都很弱，可以全部"不发"；如果当天候选都很强，仍然按相对顺序排出 P1/P2/P3，再按当天产能决定发几篇。

## 独立性纪律

Selection 只判断"今天什么素材值得生产"，**不根据未经验证的历史"爆文规律"挑题**。任何来自内容表现复盘（如标题是否为疑问句、字数长短等 Content Feature 层面的候选/待验证发现）都不得进入 Selection 的判断依据——那些研究的是文章写法层面的表现特征，不是素材选择层面的可靠规则。Selection 与 Baseline Review 保持独立。
